Who and what this covers

This policy describes the HomeSchoolHelper iOS app, its account and backup service, and this companion website. The app is intended for parents, guardians, and authorized educators managing learning records. The browser prototype is a separate design study and does not store real app records.

Information handled by the app

  • Account information: email address, account identifier, authentication credentials, and session information used by Supabase Authentication.
  • Learner and school records: learner names and grade levels; academic years and terms; courses, lessons, assignments, grades, notes, attendance, activities, reading logs, book details, portfolio metadata, schedule settings, compliance targets, and Student Mode settings entered by an adult.
  • Portfolio media: photos selected or captured for student work portfolios. The reviewed source stores image files in the app's local Application Support directory. Cloud snapshots include portfolio records and local image filenames; the reviewed backup code does not upload the image files themselves.
  • Preferences: appearance, cadence, haptics, reminder, PIN-related, and cloud-sync settings stored on the device.
  • Purchases: Apple processes subscription purchases. The app reads verified StoreKit products, transactions, and current entitlements to unlock Pro features; payment-card details are not handled by HomeSchoolHelper.
  • Support information: information you choose to send in an email or public issue. Provide only what is needed.

The reviewed source contains no third-party advertising or behavioral-analytics SDK and declares no tracking. HomeSchoolHelper does not sell family records or use them for advertising.

Why information is used

Account information authenticates access and recovery. School records power planning, progress, attendance, grades, reading, portfolios, reminders, reports, and exports. Cloud snapshots provide recovery. StoreKit information provides and manages paid features. Support information is used to investigate a request.

Camera, photos, notifications, and book lookup

Camera access is requested when you scan a book barcode or capture a portfolio photo. Photo Library access is requested when you choose an existing work sample. Barcode recognition uses Apple's VisionKit on the device. After an ISBN is scanned, the ISBN is sent to Open Library to retrieve book metadata such as title, author, page count, and subject. See the Open Library privacy information.

If you enable a daily reminder, the app requests notification permission and schedules the reminder on the device. Portfolio photos and generated exports may contain sensitive learner information; review them before sharing through the iOS share sheet.

Local storage and account access

School records are encoded as JSON in an account-specific local file. Portfolio image files are stored separately on the device. Authentication sessions use SDK-managed secure storage. The current release UI still requires a remotely verified Supabase account before opening the school workspace, even though records are local and many features operate without a continuous connection after entry. Signing out does not erase local files.

Cloud backup and restore

For a signed-in account, automatic cloud backup is enabled by default. After a record change, the app waits briefly and inserts a new snapshot into Supabase; it also attempts a snapshot when the app enters the background. You can pause automatic backup, choose Sync Now, or save a manual snapshot in Settings → Manage Backups & Restore.

A snapshot can contain the school-record fields listed above and is linked to the account ID and creation time. The current design creates successive snapshots; it is not conflict-aware live synchronization. Restoring replaces the account's local JSON records with the selected snapshot and does not restore local portfolio image files.

Owner-scoped row-level security is present in the checked-in database migration. It prevents ordinary users from reading another account's snapshots. This is not end-to-end encryption: authorized infrastructure operators may have administrative access. The app connects over HTTPS. Production deployment of the reviewed policies has not been independently verified.

Service providers and disclosures

Supabase supplies authentication and cloud database infrastructure. Apple supplies StoreKit, device permissions, notifications, and optional device backups. Open Library receives an ISBN when book lookup is used. These providers may process connection data such as IP addresses, timestamps, device or request information, and security events under their own policies.

Information may also be disclosed when legally required, to address abuse or security incidents, or at your direction. Do not enter or upload records for a family you are not authorized to represent.

Retention, deletion, and correction

Local files remain until you delete records in the app, choose Settings → Data & Storage → Erase All Device Data, or delete the app rather than offloading it. Device backups may retain copies under your Apple settings.

The development build includes in-app account deletion under Settings → Manage Backups & Restore. You can request deletion of the cloud account and backups while either preserving local school records or erasing them. The checked-in server migration defines a deletion procedure for the authenticated user, but its production deployment and end-to-end behavior must be tested before release. If the server cannot confirm deletion, local credentials may still be cleared; reconnect with support before assuming remote data was removed.

No automatic expiry schedule is defined for cloud snapshots, service logs, support messages, or infrastructure recovery copies. The app displays up to 20 recent snapshots, which is a list limit rather than a deletion limit. A final operational retention schedule remains to be published. Local editing and deletion do not rewrite earlier cloud snapshots unless those snapshots or the account are deleted.

Children's and learners' privacy

The app is designed for adults, not child account holders. Adults should enter learner information only when authorized and should use the minimum identifying information needed. The reviewed source has no public learner profiles, student messaging, advertising, or cross-app tracking.

Website and browser prototype

The website has no account form, payments, or learning-record database. It does not intentionally set analytics or advertising cookies. The browser prototype uses fictional records and page memory; reloading resets changes. Use sample information only.

The website loads Google Fonts, while the prototype also loads interface libraries from unpkg.com. Those requests expose ordinary connection information to the providers. Netlify hosts the site and may process web request logs. GitHub links lead to public pages; never post private family information there.

Contact and policy changes

The app lists privacy@homeschoolhelper.app for privacy requests and support@homeschoolhelper.app for support. These development addresses currently have no advertised MX mail route, so delivery and monitoring must be configured and tested before release. Until then, do not send learner records, identity documents, passwords, or recovery links. General, non-sensitive issues can use the public links on Support.

This policy will be revised as features and operating practices change. The date above identifies this version.
